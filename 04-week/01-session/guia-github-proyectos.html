Introducción

Esta guía te enseña paso a paso cómo configurar un proyecto completo en GitHub con gestión ágil: repositorio, etiquetas, milestones (sprints), historias de usuario como issues, tablero Kanban y plan de releases. Cada paso incluye dos formas de hacerlo:

Por Código (GitHub CLI)

Usando gh (GitHub CLI) desde la terminal. Ideal para automatizar y repetir procesos de forma rápida. Aprenderás comandos que te dan superpoderes.

Visual (Interfaz Web de GitHub)

Usando la interfaz gráfica de github.com. Ideal cuando estás aprendiendo y quieres ver cada paso de forma visual e intuitiva.

Objetivo

Al finalizar esta guía, tendrás un repositorio profesional con: 6 etiquetas personalizadas, 5 milestones (sprints), 16 historias de usuario como issues, un tablero Kanban para seguimiento visual y un plan de releases definido. Todo organizado como lo haría un equipo de desarrollo real.

Importante

Esta guía usa como ejemplo el Proyecto 12 — Sistema de Gestión Académica. Tú debes adaptar los nombres, las historias de usuario y las entidades a tu proyecto específico.

Prerrequisitos

Para ambos métodos

  • Tener una cuenta en GitHub (github.com/signup).
  • Tener Git instalado en tu computadora (git-scm.com/downloads).
  • Tener definido el plan del proyecto con: historias de usuario, sprints y releases.

Solo para el método por código (CLI)

  • Instalar GitHub CLI (gh) desde cli.github.com.
  • Autenticarse ejecutando gh auth login en la terminal.
Terminal # Verificar instalación de GitHub CLI gh --version # Autenticarse (seguir los pasos interactivos) gh auth login # Verificar autenticación gh auth status
Tip: Al ejecutar gh auth login, selecciona GitHub.com, protocolo HTTPS y autenticación con navegador web. Es la forma más sencilla.

Paso 1 — Crear el Repositorio

El repositorio es el centro de tu proyecto. Aquí vivirá el código fuente, los issues, el tablero Kanban y toda la documentación.

Visual (GitHub Web)

Crear un README.md inicial echo "# Sistema de Gestión Académica" > README.md echo "" >> README.md echo "Proyecto full-stack con NestJS + Next.js + PostgreSQL + Docker + Prisma" >> README.md # 4. Hacer el primer commit git add . git commit -m "feat: initial commit - project setup" # 5. Tip: El flag --public crea un repositorio público. Si quieres uno privado, usa --private. El flag --source=. indica que el código está en la carpeta actual.

Verifica que se creó correctamente:

Terminal # Abrir el repositorio en el navegador gh repo view --web
  1. Ve a github.com/new (o haz clic en el botón "+" en la esquina superior derecha y selecciona "New repository").
  2. En "Repository name" escribe: gestion-academica-sistema (usa el nombre de tu proyecto, sin espacios, con guiones).
  3. En "Description" escribe una descripción breve: "Sistema de Gestión Académica - NestJS + Next.js + PostgreSQL + Docker + Prisma".

  8. Para clonar el repositorio en tu computadora, copia la URL y ejecuta en la terminal: git clone https://github.com/TU_USUARIO/gestion-academica-sistema.git

Paso 4 — Crear Issues (Historias de Usuario)

Cada Historia de Usuario (HU) se documenta como un Issue en GitHub. Esto permite rastrear el progreso, asignar responsables y vincular los issues al tablero Kanban.

Formato de una Historia de Usuario

Estructura estándar de una HU

Cada issue debe contener: título descriptivo, narrativa (Como... quiero... para...), criterios de aceptación (checkboxes) y tareas técnicas.

Markdown del Issue ## HU-01 — Gestión de Estudiantes **Como** administrador académico, **quiero** registrar, consultar, editar y eliminar estudiantes, **para** mantener actualizada la información de los estudiantes. ### Criterios de Aceptación - [ ] Se puede crear un estudiante con: nombres, apellidos, código, documento, correo, fecha de nacimiento y programa. - [ ] El código estudiantil y documento son únicos. - [ ] Se puede consultar la lista con paginación. - [ ] Se puede consultar un estudiante por ID con datos completos. - [ ] Se puede editar la información. - [ ] Se puede eliminar un estudiante sin matrículas asociadas. ### Tareas Técnicas - Backend: DTOs con class-validator - Backend: Repository (Prisma queries) - Backend: Service (lógica de negocio) - Backend: Controller (endpoints CRUD) - Frontend: Página de listado - Frontend: Formulario de creación - Frontend: Página de detalle

Crear un Issue con cuerpo en Markdown

Primero, crea un archivo .md con el contenido de la HU y luego usa gh issue create:

Terminal # Paso 1: Crear un archivo temporal con el cuerpo de la HU # Puedes usar cualquier editor o echo/cat # Paso 2: Crear el issue desde el archivo gh issue create \ --title "HU-01 — Gestión de Estudiantes" \ --body-file hu-01.md \ --label "user-story,backend,frontend" \ --milestone "Sprint 1 — Infraestructura y entidades base"

Alternativa: cuerpo inline

Para issues con cuerpo breve, puedes usar --body directamente:

Terminal # Crear issue con cuerpo inline (para HUs simples) gh issue create \ --title "HU-02 — Gestión de Docentes" \ --body "**Como** administrador académico, **quiero** registrar, consultar, editar y eliminar docentes, **para** tener un registro centralizado del cuerpo docente. ### Criterios de Aceptación - [ ] Se puede crear un docente con: nombres, apellidos, documento, título, especialidad, correo y teléfono. - [ ] El documento y correo son únicos. - [ ] Se puede consultar, editar y eliminar docentes. ### Tareas Técnicas - Backend: DTOs, Repository, Service, Controller del módulo Docente - Frontend: Listado, formulario y detalle de docentes" \ --label "user-story,backend,frontend" \ --milestone "Sprint 1 — Infraestructura y entidades base"

Crear múltiples issues de forma eficiente

Si tienes muchos issues, puedes crear un script que los genere todos:

Script: crear-issues.sh #!/bin/bash # Script para crear todos los issues del proyecto # Ejecutar: bash crear-issues.sh # Sprint 1 gh issue create --title "HU-01 — Gestión de Estudiantes" \ --body-file issues/hu-01.md \ --label "user-story,backend,frontend" \ --milestone "Sprint 1 — Infraestructura y entidades base" gh issue create --title "HU-02 — Gestión de Docentes" \ --body-file issues/hu-02.md \ --label "user-story,backend,frontend" \ --milestone "Sprint 1 — Infraestructura y entidades base" gh issue create --title "HU-03 — Gestión de Programas Académicos" \ --body-file issues/hu-03.md \ --label "user-story,backend,frontend" \ --milestone "Sprint 1 — Infraestructura y entidades base" # Sprint 2 gh issue create --title "HU-04 — Gestión de Asignaturas" \ --body-file issues/hu-04.md \ --label "user-story,backend,frontend" \ --milestone "Sprint 2 — Entidades académicas" # ... repetir para HU-05 a HU-16 con sus sprints y labels correspondientes echo "✅ Todos los issues creados exitosamente"

Verifica los issues creados:

Terminal # Listar todos los issues del repositorio gh issue list --state all # Ver un issue específico gh issue view 1
  1. Ve a tu repositorio → pestaña "Issues" → clic en "New issue" (botón verde).
  2. En "Title" escribe: HU-01 — Gestión de Estudiantes
  3. En el campo de "Description" (que acepta Markdown), pega el contenido de la HU con la narrativa, criterios de aceptación y tareas técnicas.
  4. En el panel lateral derecho, haz clic en "Labels" y selecciona: user-story, backend, frontend.
  5. En "Milestone", selecciona: Sprint 1 — Infraestructura y entidades base.
  6. Opcionalmente, en "Assignees" asigna a los integrantes del equipo responsables de esa HU.
  7. Haz clic en "Submit new issue".
  8. Repite los pasos 1-7 para cada una de las 16 Historias de Usuario, asignando los labels y milestones correctos según la tabla.
Tip: Al escribir la descripción del issue, usa el formato Markdown. Los checkboxes se crean con - [ ] y se convierten en casillas interactivas que puedes marcar cuando completes cada criterio. Ejemplo:
Markdown ### Criterios de Aceptación - [ ] Se puede crear un estudiante con todos los campos - [ ] El código estudiantil es único - [ ] Se puede consultar con paginación - [x] Este criterio ya está completado ✅

Paso 5 — Crear el Tablero Kanban (GitHub Projects)

El tablero Kanban permite visualizar el progreso del proyecto con columnas (Todo, In Progress, Done). GitHub Projects V2 permite crear vistas con campos personalizados como Sprint, Release y Prioridad.

¿Qué es GitHub Projects V2?

Es la herramienta de gestión de proyectos integrada en GitHub. Funciona como un tablero Kanban avanzado donde puedes agregar issues, asignar campos personalizados (Sprint, Release, Prioridad), crear múltiples vistas (Board, Table) y filtrar/agrupar por cualquier campo.

5.1 — Crear el Proyecto

Por Código (CLI)
Visual (GitHub Web)
Terminal # Crear un nuevo proyecto de GitHub (Projects V2) gh project create --owner TU_USUARIO --title "Gestión Académica — Kanban" --format json

Si el comando anterior no funciona, utiliza la API de GraphQL:

Terminal # Alternativa: Crear proyecto via GraphQL API # 1. Obtener tu userId gh api graphql -f query='query { viewer { id login } }' # 2. Crear el proyecto (reemplaza USER_ID con el id obtenido) gh api graphql -f query=' mutation { createProjectV2(input: { ownerId: "USER_ID", title: "Gestión Académica — Kanban" }) { projectV2 { id number url } } } '
Tip: Anota el number del proyecto (ej: 1). Lo usarás en todos los comandos siguientes para referirte al proyecto.
  1. Ve a github.com → haz clic en tu foto de perfil → "Your projects".
  2. Haz clic en el botón verde "New project".
  3. Selecciona la plantilla "Board" (tablero Kanban) y haz clic en "Create project".
  4. Se abrirá el proyecto. Haz clic en el nombre del proyecto (arriba) y cámbialo a: "Gestión Académica — Kanban".
  5. El tablero se crea con 3 columnas por defecto: Todo, In Progress y Done.

5.2 — Agregar Issues al Tablero

Por Código (CLI)
Visual (GitHub Web)
Terminal # Agregar cada issue al proyecto (PROJECT_NUMBER = número del proyecto creado) # Reemplaza TU_USUARIO y PROJECT_NUMBER # Agregar issues #1 al #16 gh project item-add PROJECT_NUMBER --owner TU_USUARIO --url https://github.com/TU_USUARIO/gestion-academica-sistema/issues/1 gh project item-add PROJECT_NUMBER --owner TU_USUARIO --url https://github.com/TU_USUARIO/gestion-academica-sistema/issues/2 gh project item-add PROJECT_NUMBER --owner TU_USUARIO --url https://github.com/TU_USUARIO/gestion-academica-sistema/issues/3 # ... repetir hasta el issue #16

Agregar todos de golpe con un bucle (Bash)

Bash / Git Bash # Agregar issues #1 al #16 con un bucle for i in $(seq 1 16); do gh project item-add PROJECT_NUMBER \ --owner TU_USUARIO \ --url https://github.com/TU_USUARIO/gestion-academica-sistema/issues/$i done

Agregar todos de golpe con un bucle (PowerShell)

PowerShell # Agregar issues #1 al #16 con un bucle en PowerShell for ($i = 1; $i -le 16; $i++) { gh project item-add PROJECT_NUMBER ` --owner TU_USUARIO ` --url "https://github.com/TU_USUARIO/gestion-academica-sistema/issues/$i" }
  1. Abre tu proyecto en github.com → Tu perfil → "Your projects" → selecciona el proyecto creado.
  2. En la parte inferior de la columna "Todo", haz clic en "+ Add item".
  3. En el campo de búsqueda que aparece, escribe "#" seguido del nombre de tu repositorio. Ejemplo: #gestion-academica-sistema.
  4. Aparecerán tus issues. Haz clic en "HU-01 — Gestión de Estudiantes" para agregarlo al tablero.
  5. Repite el paso anterior para cada issue (HU-01 a HU-16).
  6. Todos los issues se agregarán a la columna "Todo" inicialmente.
Tip: Puedes arrastrar y soltar los issues entre columnas (Todo → In Progress → Done) conforme avances en el desarrollo. Esto es la esencia del Kanban.

5.3 — Crear Campos Personalizados

Para organizar el tablero por Sprint y Release, necesitas crear campos "Single Select" personalizados.

Por Código (CLI)
Visual (GitHub Web)
Terminal # Crear campo "Sprint" tipo Single Select con 5 opciones gh project field-create PROJECT_NUMBER \ --owner TU_USUARIO \ --name "Sprint" \ --data-type "SINGLE_SELECT" \ --single-select-options "Sprint 1,Sprint 2,Sprint 3,Sprint 4,Sprint 5" # Crear campo "Release" tipo Single Select con 2 opciones gh project field-create PROJECT_NUMBER \ --owner TU_USUARIO \ --name "Release" \ --data-type "SINGLE_SELECT" \ --single-select-options "Release 1 (2° Corte),Release 2 (3° Corte)" # Crear campo "Prioridad" tipo Single Select con 3 opciones gh project field-create PROJECT_NUMBER \ --owner TU_USUARIO \ --name "Prioridad" \ --data-type "SINGLE_SELECT" \ --single-select-options "Alta,Media,Baja"
  1. En tu tablero del proyecto, haz clic en el botón "+" en la cabecera de la tabla (al final de las columnas visibles), o en el menú "⚙️ Settings" del proyecto.
  2. Selecciona "+ New field".
  3. En "Field name" escribe: Sprint
  4. En "Field type" selecciona: "Single select".
  5. Agrega las opciones una por una haciendo clic en "+ Add option": Sprint 1, Sprint 2, Sprint 3, Sprint 4, Sprint 5.
  6. Haz clic en "Save".
  7. Repite los pasos 2-6 para crear el campo "Release" con opciones: Release 1 (2° Corte) y Release 2 (3° Corte).
  8. Opcionalmente, crea el campo "Prioridad" con opciones: Alta, Media, Baja.

5.4 — Asignar valores de Sprint y Release a cada Issue

Por Código (CLI)
Visual (GitHub Web)

Para asignar Sprint y Release a cada item, necesitas los IDs del campo y de las opciones. Sigue estos pasos:

Terminal # 1. Obtener los IDs de los campos personalizados gh project field-list PROJECT_NUMBER --owner TU_USUARIO --format json # 2. Obtener los IDs de los items del proyecto gh project item-list PROJECT_NUMBER --owner TU_USUARIO --format json

Con los IDs obtenidos, asigna los valores:

Terminal # Asignar Sprint a un item # Reemplaza: ITEM_ID, FIELD_ID, OPTION_ID con los valores reales gh project item-edit \ --project-id PROJECT_ID \ --id ITEM_ID \ --field-id FIELD_ID \ --single-select-option-id OPTION_ID # Ejemplo: Asignar "Sprint 1" al issue HU-01 gh project item-edit \ --project-id PVT_xxxxxxxxxxxx \ --id PVTI_xxxxxxxxxxxx \ --field-id PVTSSF_xxxxxxxxxxxx \ --single-select-option-id abc12345

Los IDs cambian en cada proyecto

Los IDs de campos (PVTSSF_), items (PVTI_), opciones y el proyecto (PVT_) son únicos. Debes obtenerlos con los comandos de arriba para tu proyecto específico. No copies los del ejemplo.

  1. En tu tablero del proyecto, cambia a la vista "Table" (ícono de tabla arriba a la izquierda). Esto te permite ver los campos en columnas.
  2. Verás tus issues con las columnas de campos. Localiza la columna "Sprint".
  3. Para cada issue, haz clic en la celda de la columna "Sprint" y selecciona el sprint correspondiente (ej: HU-01 → Sprint 1).
  4. Repite para la columna "Release": asigna Release 1 (2° Corte) a las HU-01 a HU-11, y Release 2 (3° Corte) a las HU-12 a HU-16.
  5. Opcionalmente, asigna la "Prioridad" a cada issue.

5.5 — Configurar la Vista del Tablero

Puedes crear múltiples vistas del tablero para diferentes perspectivas del proyecto:

Vista Board (Kanban)

La vista por defecto. Columnas: Todo → In Progress → Done. Agrupa por "Sprint" para ver las tareas de cada iteración.

Vista Table

Muestra todos los issues en tabla con sus campos personalizados. Ideal para asignar Sprint, Release y Prioridad rápidamente.

Vista Roadmap

Muestra los issues en una línea de tiempo. Ideal para ver el progreso general del proyecto con las fechas de cada sprint.

Configuración recomendada del tablero

  • Vista 1 — "Kanban por Sprint": Board view, Group by: Sprint → Así ves las HUs organizadas por sprint.
  • Vista 2 — "Por Release": Board view, Filter: Release = "Release 1 (2° Corte)" → Así ves solo lo del segundo corte.
  • Vista 3 — "Tabla General": Table view, sin filtros → Para editar campos rápidamente.

Paso 6 — Plan de Releases

Crear Releases en GitHub

Por Código (CLI)
Visual (GitHub Web)

Los Releases de GitHub se crean sobre un tag de Git. Primero crea el tag y luego el release:

Terminal # Cuando el Release 1 esté completo (Segundo Corte): # 1. Asegúrate de estar en la rama principal con todo actualizado git checkout main git pull # 2. Crear un tag de versión git tag -a v1.0.0 -m "Release 1: Backend + Frontend Base - Segundo Corte" git push origin v1.0.0 # 3. Crear el release en GitHub gh release create v1.0.0 \ --title "Release 1 — Segundo Corte" \ --notes "## Release 1 — Backend + Frontend Base ### Incluye: - API REST completa con arquitectura Controller → Service → Repository - CRUD de todas las entidades: Estudiante, Docente, Programa, Asignatura, Período, Asignación, Matrícula, Calificación - Common Module: Filters, Interceptors, Pipes - Frontend base con listados y formularios - Docker Compose funcional ### Sprints completados: - Sprint 1: Infraestructura y entidades base - Sprint 2: Entidades académicas - Sprint 3: Matrícula, Calificaciones y Frontend base ### HUs cerradas: HU-01 a HU-11"
Terminal # Cuando el Release 2 esté completo (Tercer Corte): git tag -a v2.0.0 -m "Release 2: Integración + Reportes - Tercer Corte" git push origin v2.0.0 gh release create v2.0.0 \ --title "Release 2 — Tercer Corte" \ --notes "## Release 2 — Integración + Reportes ### Incluye: - Frontend completo con formularios dinámicos - Navegación y layout responsivo - Historial académico del estudiante - Reporte de matriculados por asignatura - Cálculo de promedio acumulado ponderado - Pruebas de integración E2E ### Sprints completados: - Sprint 4: Frontend avanzado e integración - Sprint 5: Reportes, promedio y cierre ### HUs cerradas: HU-12 a HU-16"
  1. Ve a tu repositorio en GitHub → en el panel lateral derecho, haz clic en "Releases" (o ve a la URL: github.com/TU_USUARIO/tu-repo/releases).
  2. Haz clic en "Create a new release" (o "Draft a new release").
  3. En "Choose a tag", escribe v1.0.0 y selecciona "Create new tag: v1.0.0 on publish".
  4. En "Release title" escribe: Release 1 — Segundo Corte
  5. En el campo de "Description", escribe un resumen del release (qué se entrega, sprints completados, HUs cerradas). Puedes usar Markdown.
  6. Si es un release de prueba, marca "Set as a pre-release". Si es definitivo, déjalo desmarcado.
  7. Haz clic en "Publish release".
  8. Repite los pasos para el Release 2 con el tag v2.0.0 cuando completes el tercer corte.
Tip: Los releases de GitHub son como "fotografías" de tu código en un momento dado. Cualquier persona puede descargar el código fuente de cada release como un archivo ZIP o TAR.

Flujo de Trabajo Diario

1

Seleccionar una HU del Sprint actual

Ve al tablero Kanban → columna "Todo" → elige una HU del sprint actual y muévela a "In Progress".

2

Crear rama de trabajo

Crea una rama desde main con el nombre de la HU: git checkout -b feature/HU-01-gestion-estudiantes

3

Desarrollar y hacer commits

Implementa la HU (Backend + Frontend). Haz commits descriptivos: git commit -m "feat(estudiante): add CRUD endpoints"

4

Push y Pull Request

Sube la rama: git push origin feature/HU-01-gestion-estudiantes. Crea un Pull Request en GitHub vinculando el issue: Closes #1.

5

Mover a Done

Al mergear el PR, mueve la HU a "Done" en el tablero Kanban. El issue se cierra automáticamente si usaste Closes #N.
