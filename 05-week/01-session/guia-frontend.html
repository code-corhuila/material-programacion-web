Introducción

En esta guía vas a construir desde cero el frontend del Sistema de Gestión Académica. Aprenderás a estructurar un proyecto Next.js 15 con App Router, crear un cliente HTTP centralizado, definir interfaces TypeScript para las 8 entidades del sistema e implementar servicios que consumen la API REST del backend.

¿Qué vas a construir?

Una aplicación web con navegación por Sidebar, 8 módulos CRUD (Programas, Estudiantes, Docentes, Asignaturas, Períodos, Asignaciones, Matrículas, Calificaciones) que consumen los endpoints /api/v1 del backend NestJS mediante un cliente HTTP tipado con TypeScript.

Prerrequisito

Esta guía es la segunda parte del proyecto. El backend con NestJS, Prisma y PostgreSQL debe estar funcionando antes de comenzar. Consulta la Guía Backend si no lo has hecho.
▲

Framework — Next.js 15

Framework React con App Router, Server Components, metadata API y routing basado en carpetas. Corre en el puerto 3000.

UI — React 19

Librería de componentes con Hooks modernos. Usada con 'use client' para componentes interactivos como el Sidebar.

Estilos — Tailwind CSS 3

Framework CSS utility-first. Clases de utilidad aplicadas directamente en los componentes JSX. Sin archivos CSS adicionales.

Tipado — TypeScript 5

Interfaz tipada para las 8 entidades del sistema. Detecta errores en tiempo de compilación antes de que lleguen al navegador.

Arquitectura del Frontend

El Frontend sigue el patrón App Router de Next.js 15. Cada módulo del sistema tiene su propia ruta dentro del grupo (dashboard). Los servicios encapsulan las llamadas a la API y las interfaces definen los contratos de datos con el backend.

FlujoNavegador └─▶ Next.js :3000 └─▶ App Router (src/app/) ├── page.tsx → redirect('/dashboard') └── (dashboard)/ ├── layout.tsx → DashboardLayout + Sidebar └── [módulo]/page.tsx └─▶ services/[módulo].service.ts └─▶ lib/api.ts (fetch) └─▶ NestJS :3001/api/v1/[recurso]

Flujo de datos

Página React → llama a servicio → invoca lib/api.ts → fetch HTTP → NestJS :3001/api/v1 → responde { data: [...] } → el servicio retorna el array tipado.

Configurar next.config.ts

Expone la URL del backend como variable de entorno al cliente

El archivo next.config.ts expone la variable NEXT_PUBLIC_API_URL con un valor por defecto en caso de que no esté definida en el sistema. Reemplaza el contenido generado por create-next-app.

frontend/next.config.tsimport type { NextConfig } from 'next'; const nextConfig: NextConfig = { env: { NEXT_PUBLIC_API_URL: process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3001', }, }; export default nextConfig;

Prefijo NEXT_PUBLIC_

Solo las variables que empiezan con NEXT_PUBLIC_ son accesibles en el navegador (client-side). Las demás solo están disponibles en el servidor de Node.js. Nunca pongas secretos en variables NEXT_PUBLIC_.

Crear el cliente HTTP — lib/api.ts

Funciones reutilizables para todos los métodos HTTP con manejo de errores

  • Crea la carpeta src/lib/ dentro de frontend/.
  • Crea el archivo api.ts con las cuatro funciones HTTP genéricas: apiGet, apiPost, apiPut, apiDelete.
  • Cada función agrega automáticamente el prefijo /api/v1 a la ruta, por lo que los servicios solo pasan la ruta relativa.
frontend/src/lib/api.ts// Cliente HTTP centralizado para la API REST del backend NestJS // Base URL configurable desde variable de entorno NEXT_PUBLIC_API_URL const BASE_URL = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3001'; export async function apiGet<T>(path: string): Promise<T> { const res = await fetch(`${BASE_URL}/api/v1${path}`); if (!res.ok) throw new Error(`GET ${path} failed: ${res.status}`); const json = await res.json(); return json.data as T; } export async function apiPost<T>(path: string, body: unknown): Promise<T> { const res = await fetch(`${BASE_URL}/api/v1${path}`, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(body), }); if (!res.ok) throw new Error(`POST ${path} failed: ${res.status}`); const json = await res.json(); return json.data as T; } export async function apiPut<T>(path: string, body: unknown): Promise<T> { const res = await fetch(`${BASE_URL}/api/v1${path}`, { method: 'PUT', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(body), }); if (!res.ok) throw new Error(`PUT ${path} failed: ${res.status}`); const json = await res.json(); return json.data as T; } export async function apiDelete<T>(path: string): Promise<T> { const res = await fetch(`${BASE_URL}/api/v1${path}`, { method: 'DELETE' }); if (!res.ok) throw new Error(`DELETE ${path} failed: ${res.status}`); const json = await res.json(); return json.data as T; }

¿Por qué json.data?

El backend NestJS usa un ResponseInterceptor que envuelve todas las respuestas en { "data": ..., "message": "...", "statusCode": 200 }. Por eso se accede a json.data para obtener el resultado real.
Tip — Genéricos TypeScript: El parámetro <T> permite que TypeScript infiera el tipo de retorno. Por ejemplo: apiGet<Estudiante[]>('/estudiantes') devuelve Promise<Estudiante[]> con autocompletado completo.

Una función CRUD por cada entidad usando el cliente HTTP de lib/api.ts

Cada servicio exporta un objeto con los métodos findAll, findOne, create, update y remove. También define los DTOs de creación y actualización.

Grupos de rutas en App Router

Las carpetas con paréntesis como (dashboard) son grupos de rutas — organizan archivos sin afectar la URL. La ruta /dashboard existe, no /(dashboard)/dashboard.

Dockerfile — Contenedor de producción

Imagen Docker multi-stage para el frontend Next.js

El Dockerfile usa dos etapas: builder (compila la app) y production (imagen mínima que solo sirve los archivos compilados).

frontend/Dockerfile# ============================================================ # Etapa 1 — Builder: instala dependencias y compila Next.js # ============================================================ FROM node:22-alpine AS builder WORKDIR /app COPY package*.json ./ RUN npm ci COPY . . RUN npm run build # ============================================================ # Etapa 2 — Production: imagen mínima para servir la app # ============================================================ FROM node:22-alpine AS production WORKDIR /app ENV NODE_ENV=production # Copia los artefactos del build desde la etapa builder COPY --from=builder /app/.next/standalone ./ COPY --from=builder /app/.next/static ./.next/static COPY --from=builder /app/public ./public EXPOSE 3000 CMD ["node", "server.js"]

Standalone output en next.config.ts

Para que el Dockerfile funcione correctamente, agrega output: 'standalone' en next.config.ts:
frontend/next.config.tsconst nextConfig: NextConfig = { output: 'standalone', // ← habilita la salida standalone para Docker env: { NEXT_PUBLIC_API_URL: process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3001', }, };

Agregar el servicio frontend a Docker Compose

Si quieres ejecutar el frontend junto con la base de datos usando Docker Compose, agrega este servicio en el docker-compose.yml raíz:

docker-compose.yml — fragmento a agregar frontend: build: context: ./frontend dockerfile: Dockerfile container_name: gestion_academica_frontend ports: - '3000:3000' environment: NEXT_PUBLIC_API_URL: http://backend:3001 depends_on: - backend

Glosario

TérminoDefinición
App RouterSistema de enrutamiento de Next.js 13+. Las carpetas dentro de app/ definen rutas. Soporta layouts anidados y Server Components.
Server ComponentComponente React que se renderiza en el servidor de Node.js. No tiene acceso a hooks del navegador (useState, useEffect). Modo por defecto en App Router.
Client ComponentComponente que se renderiza en el navegador. Se declara con 'use client'. Puede usar hooks, eventos y APIs del DOM.
Route GroupCarpeta con nombre entre paréntesis como (dashboard). Agrupa rutas y layouts sin afectar la URL real.
Barrel exportArchivo index.ts que re-exporta múltiples módulos desde un único punto de entrada. Simplifica las importaciones.
Tailwind CSSFramework CSS utility-first. Los estilos se aplican usando clases utilitarias directamente en el JSX en lugar de archivos .css separados.
Generic TypeScript <T>Parámetro de tipo que permite que una función trabaje con múltiples tipos manteniendo el tipado. apiGet<Estudiante[]> devuelve Promise<Estudiante[]>.
Omit<T, K>Utilidad TypeScript que crea un nuevo tipo excluyendo las propiedades K de T. Usado para DTOs: Omit<Estudiante, 'id' | 'createdAt'>.
Partial<T>Utilidad TypeScript que hace todas las propiedades opcionales. Usado para DTOs de actualización (PATCH / PUT parcial).
HU (Historia de Usuario)Unidad de trabajo del backlog. En este proyecto cada HU corresponde a un módulo CRUD (HU-01: Estudiantes, HU-02: Docentes, etc.).
StubImplementación mínima temporal de una función o componente. Permite compilar el proyecto mientras se desarrolla la lógica real en los Sprint siguientes.
CORSPolítica del navegador que bloquea peticiones HTTP entre dominios/puertos distintos. El backend debe permitir explícitamente http://localhost:3000.
